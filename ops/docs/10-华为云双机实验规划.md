# 华为云双机实验规划（开第二台之前先看这份）

> 变化：之前 `遇到的问题与解决方案.md §4`（PD 分离）和 `kimi3_ops/docs/07`（HCCL 多机）
> 都因为「只有 1 个节点、无 RoCE」被标成**做不了**。现在你能开第二台昇腾实例 →
> **这两块从"文档"变成"可实测"**。
>
> 但先别急着开——**开错规格要重开，8 卡实例按小时计费，是烧钱的**。

---

## 0. 最重要的一条建议：**先开一台，别再开一台**

```
第一步：只开一台 → 验证规格对不对（有没有 RoCE、CANN 装没装好、卡数够不够）
第二步：确认无误 → 再开第二台，且必须同 AZ / 同 VPC / 同安全组
```

理由：**RoCE 是这个规划的唯一命门**。如果规格不带 RoCE，两台都开出来也做不了跨机 RDMA，
PD 分离的 KV 传输也会退化。先花一台的钱把这件事确认掉。

---

## 1. 开实例时的四个关键决策

| # | 决策 | 怎么选 | 选错的后果 |
|---|---|---|---|
| 1 | **规格带不带 RoCE** | 看规格详情里的 RDMA/RoCE 字段（一般是裸金属规格才有）；**不确定就问客服** | 跨机 RDMA、PD 分离全做不了 |
| 2 | **同可用区 AZ** | 两台必须同 AZ | **跨 AZ 的 RoCE 基本不通**，HCCL 会退化甚至建链失败 |
| 3 | **同 VPC + 同子网 + 同安全组** | 内网互通的前提 | 互相 ping 不通 |
| 4 | **镜像** | 优先选预装 CANN 的昇腾镜像 | 自己装驱动+固件，半天起步 |

> 另外：**做 RDMA 和 HCCL 多机验证，不需要 8 卡规格**。2 台 × 1~2 卡就能把流程跑通，
> 等要跑 PD 分离的大模型时再上大规格。**先用小规格验证，再按需扩容。**

## 2. 验证阶梯（逐级过，别跳级）

### L0 · 基础环境（两台各自）

```bash
npu-smi info                                    # 卡数 / 型号 / HBM
python3 -c "import torch, torch_npu; print(torch.npu.device_count())"
ping <另一台内网IP>                              # ★ 先确认网络通
```

### L1 · 网络能力（**这级决定后面所有事**）

```bash
# ① RDMA 设备有没有
ibv_devices
ibv_devinfo | grep -E "hca_id|link_layer|state|rate"

# ② ★★★ 昇腾专属：NPU 之间的 RoCE 连通性（最该先跑这条）
hccn_tool -i 0 -link -g
hccn_tool -i 0 -net_health -g
hccn_tool -i 0 -ip -g
hccn_tool -i 0 -ping -g address <对端NPU的IP>       # ← 通了才谈后面

# ③ 跨机 RDMA 真带宽（RDMA 那条线的核心数字）
ib_write_bw -d <dev> -g <gid>                      # A 机
ib_write_bw -d <dev> -g <gid> <A机IP>               # B 机
```

> **为什么 `hccn_tool -ping` 比 `ib_write_bw` 更该先跑**：前者验的是"NPU 之间的 RoCE 通路"，
> 后者只验"host 网卡之间的 RDMA"。HCCL 走的是前者，前者不通的话后面全是白费。

### L2 · HCCL 单机多卡

```bash
cd /usr/local/Ascend/<cann>/tools/hccl_test
make MPI_HOME=/path/to/mpi ASCEND_DIR=$ASCEND_HOME_PATH
mpirun -n 8 ./bin/all_reduce_test -b 8K -e 64M -f 2 -d fp32 -o sum -p 8
```

### L3 · HCCL 多机（**首次跨机**）

```bash
# hostfile：每行「节点IP:每节点进程数」
cat > hostfile <<'EOF'
192.168.0.10:8
192.168.0.11:8
EOF

# 两台都要设：指定 HCCL 用哪张网卡建链（★ 写错必失败）
export HCCL_SOCKET_IFNAME=<RoCE网卡名>
mpirun -f hostfile -n 16 ./bin/all_reduce_test -b 8K -e 64M -f 2 -d fp32 -o sum -p 8
```

### L4 · PD 分离（最终目标）

按 `遇到的问题与解决方案.md §4.2` 的 vLLM-Ascend / SGLang 配置跑。
此时 §4.3 的 connector 选型（Layerwise push）才真正有意义。

## 3. 多机必配的环境变量（踩坑清单）

```bash
export HCCL_SOCKET_IFNAME=<RoCE网卡名>     # ★ 最常出错的一个：不指定就选错网卡
export HCCL_IF_IP=<本机 RoCE IP>
export TP_SOCKET_IFNAME=<同上>
export GLOO_SOCKET_IFNAME=<同上>
export HCCL_RDMA_TIMEOUT=17                # 大集群调大
export HCCL_EXEC_TIMEOUT=...
export ASCEND_CONNECT_TIMEOUT=...
export ASCEND_TRANSFER_TIMEOUT=...
```

| 坑 | 现象 | 处理 |
|---|---|---|
| 安全组没开端口 | 建链超时 | **按华为云 HCCL 部署文档的安全组要求开端口**（HCCL master / device 端口段） |
| `HCCL_SOCKET_IFNAME` 没设 | 选到管理网 | 显式指定 RoCE 网卡名（`ip -br link` 看） |
| 两台驱动/CANN 版本不一致 | 建链失败或精度异常 | 版本必须完全对齐 |
| 跨 AZ | RoCE 不通 | 两台必须同 AZ |
| MTU 不一致 | 大包丢/慢 | 两端 `ip link` 核对 MTU 与 RoCE 网卡的 PFC 配置 |
| 时钟不同步 | 分布式日志难对齐 | 两台都开 NTP |

## 4. 优先级（按"价值 ÷ 成本"）

| 序 | 实验 | 解锁的价值 | 成本 |
|---|---|---|---|
| 1 | **L1 的 `hccn_tool -ping` + `ib_write_bw`** | RDMA 那条线**唯一的真数字** | 极低（2 台小规格） |
| 2 | **L3 HCCL 多机 AllReduce** | 集合通信实测（`docs/07` 的缺口） | 低 |
| 3 | **算子编译 + 对拍 + 达标率**（单机即可） | 消掉"未验证代码"风险（`docs/09` 的 P0） | 低 |
| 4 | **L4 PD 分离** | `§4` 落地的完整故事 + KV 传输占比 | **高**（要跑模型，规格要大） |
| 5 | K3 部署方案的规模验证 | `kimi3_deploy/` 的账变实测 | 很高（几十卡） |

> 顺序建议：**1 → 3 → 2 → 4**。
> 先拿最便宜的两台把 RDMA 真数字拿到（这是唯一在别处拿不到的），
> 顺手在单机上把算子编译验证做掉（消风险），再考虑花钱跑 PD 分离。

---

## 5. 一句话总结

**第二台实例的价值不是"更多卡"，是"第一次拥有跨机链路"。**
有了它，你手上三份材料能同时兑现：
- `rdma_host_demo/` → 真带宽数字
- `kimi3_ops/docs/07` → HCCL 多机从文档变实测
- `遇到的问题与解决方案.md §4` → PD 分离真正跑起来

**但请先开一台验规格**——RoCE 有没有，决定后面 80% 的实验做不做得成。
